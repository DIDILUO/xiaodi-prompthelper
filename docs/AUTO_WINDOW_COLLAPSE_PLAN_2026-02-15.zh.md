# 自动折叠整窗功能实施计划（2026-02-15）

## 目标
- 在“刷新面板”按钮右侧新增“自动折叠”按钮（图标+小字）。
- 开启后：窗口失焦时自动折叠为“微型控制台窗口”。
- 鼠标悬停到折叠窗口上时自动展开（不销毁组件，不重渲染整树，只做窗口尺寸与可见性切换）。
- 折叠态尺寸增大（仅尺寸变化，微型控制台的图标与文本不改）。
- 保持低开销、过渡顺滑、轻量动画。

## 设计要点
1. 主进程折叠状态机
- 在主进程提供显式接口（设置折叠/获取折叠状态），避免仅靠 toggle 造成状态反转竞态。
- 保留现有快捷键折叠能力，并统一通过同一状态机。
- 折叠高度常量上调（比当前 64 更大）。

2. 渲染层“无重建”折叠
- 不使用条件渲染卸载页面主体。
- 通过 `.panel.is-window-collapsed` 类隐藏顶部与主内容，仅显示底部微型控制台。
- 控制台详情区在整窗折叠态强制隐藏，仅保留微型控制台头部。

3. 自动折叠触发
- 新增“自动折叠”开关（本地持久化）。
- 开启后监听失焦事件，触发整窗折叠。
- 折叠后在微型控制台区域悬停触发展开。
- 增加轻量防抖/防抖动锁，避免频繁折叠展开抖动。

4. 动画与性能
- 只做 opacity/transform 级别轻动画（短时长）。
- 不引入高频轮询，不做昂贵布局反复计算。
- 使用现有 refs，避免新增大规模状态联动。

## 验收标准
- 视觉：按钮位置正确（刷新右侧），折叠窗口尺寸明显大于当前，UI过渡平滑。
- 逻辑：
  - 开启自动折叠后，失焦自动折叠。
  - 鼠标移入折叠窗口后自动展开。
  - 未开启自动折叠时，不触发上述自动行为。
- 稳定性：
  - 不出现整页重渲染导致的闪烁。
  - 不破坏当前预览区/控制台手动折叠逻辑。
  - 不影响现有 IPC、桥接、日志行为。
