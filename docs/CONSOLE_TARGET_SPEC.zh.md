# 大控制台日志重构目标规格（发布前冻结 v2）

更新时间：2026-02-16  
适用范围：`webui` 大控制台（不含微型控制台 UI 皮肤本身）

## 1. 目标

本规格用于把当前日志链路重构为“可读、可排障、可导出、低刷屏”的统一体系，解决以下问题：

1. 短时中间态日志过多，影响可读性。
2. 同类错误重复刷屏，缺少折叠与聚合。
3. 修复指引存在场景错配（如桥接错误被提示为 API Key 问题）。
4. 大控制台与微型控制台职责边界不够明确。

## 2. 角色定位

1. 大控制台：面向问题定位与链路复盘（详情、耗时、修复指引）。
2. 微型控制台：面向状态摘要（短文案、低频变化，不展示细节）。
3. 导出日志：面向开发调试（Raw）与用户回报问题（Wrapped）。

## 3. 输入来源（按当前代码链路）

1. `appendLog(...)`：通用日志入口。
2. `appendTraceLog(...)`：带域/阶段/耗时的包装入口。
3. `bridge /status` + `bridge /ps/logs`：插件状态与插件日志上报。
4. 聊天与跑图请求链路（发送、返回、失败、中止）。
5. 取图/回传链路（发送、返回、失败、目标画布选择）。

## 4. 统一日志模型（Wrapped）

```ts
type ConsoleViewLog = {
  id: string;
  ts: string; // HH:mm:ss
  level: "info" | "warn" | "error";
  type: "system" | "api" | "bridge" | "dev";
  typeLabel: "系统" | "API" | "桥接" | "开发";
  message: string;        // 主文案（可多行）
  state?: "info" | "running" | "success" | "warn" | "error";
  requestId?: string;
  durationMs?: number;
  guide?: string;
  foldKey?: string;
  repeatCount?: number;
};
```

## 5. 展示规范

### 5.1 排版

1. 时间固定宽度。
2. 类型后仅一个空格。
3. 正文行距统一，不允许“同类日志不同行高”。

### 5.2 正文颜色

1. 白色：`info / running / success / warn`。
2. 红色：`error`。

注：类型标签可保留现有彩色体系；正文只允许白/红两类。

### 5.3 文案原则

1. 一条日志只表达一个动作结果。
2. 中间态不刷屏；优先展示“结果态（成功/失败）”。
3. 默认避免“发送时间/返回时间”冗余字段，仅保留耗时。

## 6. 文案模板（强约束）

### 6.1 连通验证

1. `[API] 聊天 API 连通验证成功`
2. `[API] 跑图 API 连通验证成功`
3. 失败：`[API] 聊天 API 连通验证失败：{原因}`
4. 失败：`[API] 跑图 API 连通验证失败：{原因}`

### 6.2 聊天链路

1. 发送：`[API] 聊天请求已发送`（仅在请求开始时写 1 条）
2. 成功：`[API] 聊天请求已返回：成功，返回 {n} 字，耗时 {ms}ms`
3. 失败：`[API] 聊天请求失败：{原因}` + 修复指引
4. 中止：`[API] 聊天已中止`

### 6.3 跑图链路

1. 发送：`[API] 跑图请求已发送：数量 x{n}`
2. 成功：`[API] 跑图请求已返回：收到 {n} 张，耗时 {ms}ms`
3. 失败：`[API] 跑图请求失败：{原因}` + 修复指引
4. 中止：`[API] 跑图队列已中止`

### 6.4 桥接链路

1. 状态变更：`[桥接] 插件连接状态变更：插件已连接/连接中/待连接`
2. 取图成功：`[桥接] 取图已完成：{选区|全图|本地}，耗时 {ms}ms`
3. 回传成功：`[桥接] 回传已完成：已导入到 Ps`
4. 回传失败：`[桥接] 回传失败：{原因}` + 修复指引

## 7. 去刷屏与折叠策略

### 7.1 折叠键

`foldKey = type + domain + phase + normalizedError + guide`

### 7.2 折叠窗口

1. 同 `foldKey` 在 30s 内聚合为一条。
2. `repeatCount` 增长并更新时间戳，不重复新增行。

### 7.3 中间态抑制

1. 小于 1s 的“发送中/处理中”不单独输出。
2. 轮询成功（无状态变化）不输出。
3. 仅“状态变更”写日志（例如 插件待连接 -> 插件已连接）。

## 8. 修复指引映射（场景优先）

### 8.1 场景优先级

1. 先按 `scene`（chat/image/bridge）映射。
2. 再按错误关键字映射。
3. 最后走通用兜底。

### 8.2 关键错误强制映射

1. `invalid file token used / import_file_token_missing / import_temp_file_path_empty`  
   指引：`Ps 回传文件令牌无效；请重试回传。若仍失败，请重载 Ps 插件后再试。`
2. `encodeImageData returned empty / empty png payload / image data with alpha cannot be encoded as jpeg`  
   指引：`Ps 抓图编码失败；请重载插件后重试。必要时切换抓图方式。`
3. `no selection / 无选区`  
   指引：`未检测到选区；请先在 Ps 中创建选区。`

### 8.3 429 专项（新增）

日志标题：`请求失败：429（额度或限流）`

正文与指引必须体现三点：

1. Key 额度不足或欠费；
2. 请求频率过高触发限流；
3. 分组/渠道对当前模型不可用。

统一修复指引：

`请先检查额度与分组渠道，再降低请求频率后重试；必要时切换模型或服务商。`

## 9. 微型控制台协同规则

1. 微型控制台仅显示 7 字内状态词。
2. 大控制台负责原因、耗时、修复指引。
3. 微型控制台错误提示统一引导：`请打开大控制台查看修复指引。`

## 10. 导出规范

导出必须包含两份：

1. `raw.log`（完整原始链路）
2. `wrapped.log`（用户可读链路）

并带元信息：

1. 导出时间；
2. 版本号；
3. 配置摘要（地址/模型/兼容格式，密钥脱敏）。

## 11. 性能约束

1. 日志数组上限：200 条（超出即丢弃最旧）。
2. 折叠更新优先原位聚合，避免高频数组扩容。
3. 自动滚动仅在控制台展开且用户未手动上滚时执行。
4. 日志层不允许触发额外计费请求（严禁“为验证而发真实业务请求”）。

## 12. 实施阶段（本轮）

### P0（必须）

1. 统一文案模板与状态词。
2. 删除冗余“发送时间/返回时间”字段。
3. 加入 429 专项映射与桥接专项映射。

### P1（必须）

1. 折叠去重（30s 窗口）。
2. 中间态抑制（<1s 不落盘）。
3. 结果态优先输出。

### P2（建议）

1. Raw/Wrapped 导出一致性校验。
2. 错误码与修复指引映射单测。

## 13. 验收清单

1. 聊天成功链路：仅“发送 + 返回(耗时)”两条。
2. 跑图成功链路：仅“发送 + 返回(张数+耗时)”两条。
3. 429：文案与修复指引命中专项模板。
4. 桥接错误：不再出现 API Key 误导指引。
5. 同错误连续触发：显示折叠计数，不刷屏。
6. 微型控制台与大控制台文案一致且职责分离。
